COMMANDES DE LINUX-0 SOUS KERNEL16UNIX (compilees par LPC /X)
==============================================================

Banc d'essai : noyau KERNEL16UNIX amorce sous QEMU (1 Mo, console serie et
ecran VGA), commandes compilees avec "lpc /X" puis installees dans /bin. Les
commandes de style DOS (Uses DOS, Crt) ont ete comparees aux executables DOS
de BIN16 sous DOSBox : memes fichiers d'essai (fins de ligne CR LF cote DOS,
LF cote LINUX-0).

ETAT : marche    = fonctionne comme sous DOS (ou conformement a l'aide de la
                   commande) pour les essais faits;
       reserves  = fonctionne mais avec une limite, expliquee dans REMARQUE;
       echoue    = ne fonctionne pas, la cause est indiquee.
ESSAI : l'essai fait; "aide /?" = la commande demarre et affiche son aide
(le shell developpe /? : l'ecrire '/?').

Resume : 167 marchent, 15 avec reserves, 4 echouent (sur 186 programmes).

Causes frequentes
-----------------
 1. Fins de ligne : plusieurs commandes DOS separent les lignes par CR : sur
    les fichiers texte LF de LINUX-0 elles ne coupent pas les lignes (tail,
    tac, fold).
 2. Memoire : l'image d'un processus 8086 n'est pas deplacable, l'appel break
    ne peut donc agrandir le tas que si la memoire qui suit est libre. Les
    commandes qui allouent beaucoup reservent leur tas des l'exec par une
    directive {$IFDEF LPC}{$M pile,tasmin,tasmax}{$ENDIF} (diff, join,
    make, ldd). Pendant exec, le pere d'un vfork (le shell) peut etre
    ecrit dans la zone de va-et-vient : gpic, groff, lex, myisamchk
    s'executent donc depuis sh (avec un disque dur; une disquette n'a pas
    de zone de va-et-vient).
 3. Defauts des commandes elles-memes, identiques sous DOS : sort -r -n -u
    (erreur 002), uniq -c -d (103), paste (202).
 4. Programmes DOS : which cherche dans un PATH separe par ";".
